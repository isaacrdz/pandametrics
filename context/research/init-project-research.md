# Init Project

## Output

`docs/init-project.md`

## Research

Document how to clean the Create Next App boilerplate so the index (`/`) only renders an `<h1>` that says "Panda Metrics", and how to connect the local repository to `git@github.com:Ellyonsoft/panda-metrics.git` and push the first commit.

## Include

Current state: what the boilerplate ships today (`app/page.tsx` with the Next.js logo, links and Deploy/Docs buttons, `app/layout.tsx` with Geist fonts and "Create Next App" metadata, `app/globals.css` with the default theme tokens, the SVGs in `public/`, the default `README.md`), the Next.js 16 / React 19 / Tailwind v4 versions in `package.json`, that the app lives in `app/` (not `src/app/` as the coding standards expect), and the git state (single "Initial commit from Create Next App", branch `main`, no remote, untracked `.claude/` and `context/`)

Cleanup: every file to change or delete, and the exact result for each:

- `app/page.tsx`: a Server Component that returns only `<h1>Panda Metrics</h1>` (with minimal Tailwind classes to center it), no `next/image` import
- `app/layout.tsx`: metadata title "Panda Metrics" and a real description, `lang` decision (`es` or `en`, given next-intl comes later), keep or drop the Geist fonts
- `app/globals.css`: keep `@import "tailwindcss"` and the `@theme` tokens, remove the `Arial` override that conflicts with `--font-sans`
- `public/`: which boilerplate SVGs are unused after the cleanup and can be removed
- `README.md`: replace the Create Next App text with a short project description and how to run it (`yarn dev`)
- Whether to move `app/` to `src/app/` now (and update `tsconfig.json` paths) to match `context/coding-standars.md`, or leave it for a later feature
- The `AGENTS.md` block generated by `next dev`: commit it as is

Verification: `yarn lint` and `yarn build` pass, and `yarn dev` shows only "Panda Metrics" at `http://localhost:3000`. Check `node_modules/next/dist/docs/` for any Next.js 16 change that affects `page.tsx`, `layout.tsx` or `LayoutProps`

Repository: step-by-step commands to connect and publish:

- Confirm SSH access to GitHub (`ssh -T git@github.com`)
- Check whether the remote repository is empty or already has commits (README, license); if it does, how to integrate them (`git pull --rebase` or `--allow-unrelated-histories`) instead of force-pushing
- `git remote add origin git@github.com:Ellyonsoft/panda-metrics.git`
- What to commit (cleanup + `context/` + `.claude/`), what must stay ignored (`.next/`, `node_modules/`, `.env*`, `.claude/settings.local.json`), and whether `.gitignore` needs updating
- Commit message for the cleanup, then `git push -u origin main`
- Confirm the default branch on GitHub is `main`

Recommendation: the minimal set of changes that leaves a clean base for Phase 1 (Foundation checklist in the project overview), and anything that should be postponed to its own feature (shadcn/ui, next-intl, Prisma, `src/` move)
